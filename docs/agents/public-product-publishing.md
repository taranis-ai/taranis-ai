# Public Product Publishing

## When To Load

Product copy/type changes, Taranis Publisher, `/reports/<product-id>`, or persisted public reports.

## Contracts

- Product creation and row deletion use native links and POST forms enhanced by HTMX, so both workflows remain available when JavaScript is disabled. On an existing product, compatible report items are also rendered as a native checkbox table inside a `noscript` fallback; the Alpine-powered searchable table remains the enhanced JavaScript experience.
- The enhanced report picker uses `x-cloak` until Alpine initializes. Do not hide it with CSS inside the `noscript` fallback: HTMX's fragment parser activates that style after create/save and hides the picker even with JavaScript enabled.
- Create copy opens `/publish/0?copy_from=<id>` without writing. Prefill type, title plus " Copy", description, and Report Items only; render/publication fields start empty. Fetch `/api/publish/product-metadata/<id>` through user-scoped persistence without reading the deferred render (404 if missing, 403 if the Product Type is inaccessible), retain unsaved-edit discard confirmation, and save through ordinary creation.
- With no reports, any ACL-visible Product Type is allowed. Otherwise the type must support every selected typed report; untyped legacy reports impose no restriction. `ProductType.supports_report_types` owns compatibility for choices and writes. Reject missing (404), hidden (403), or incompatible (400) types before creation or rendering. A type change clears the render; a MIME change also clears/disables publication until republished.
- Startup idempotently restores the non-deletable built-in `TARANIS_PUBLISHER` preset after worker types exist; additional presets are allowed.
- Presenter callbacks carry a hash of the exact render inputs. Reject stale/missing revisions rather than overwriting newer product state.
- Publishing copies the current render through a worker-key-protected endpoint into `<resolved DATA_FOLDER>/published-reports/<product-id>` (containers use `/app/data`). Use atomic replacement and update `last_published_url` only on success; failures retain the previous URL.
- `/reports/<product-id>` is intentionally unauthenticated, proxied to core, and served with the product MIME type, sandbox, and no-sniff headers. A MIME-changing edit disables this route even while the old file remains for replacement.
- Intended functionality / clarified requirement: authorized analysts may author HTML in Story summaries and include it in generated HTML products through templates such as `<div>{{ story.summary }}</div>`. Assess Story cards escape the summary; product templates decide whether to render HTML or apply `|e` for plain text. Do not impose blanket stripping or escaping. `ImmutableSandboxedEnvironment` restricts server-side Jinja operations, not HTML content. The preview iframe's `sandbox` and the published response's sandbox CSP protect browser contexts separately; neither guarantees every output is safe. Template path and sandbox hardening: [#780](https://github.com/taranis-ai/taranis-ai/pull/780).
- Paths and canonical public URLs use the database-reloaded UUID, never the raw request value. Publication links must be same-origin root-relative or absolute HTTP(S), without credentials/whitespace; reject unsafe hrefs.
- Report/product request schemas remain closed to undeclared fields.
- Product lists load Type labels and Report IDs without report attributes or renders. Search joins the actual Product Type before ACL filtering/counting. Sorts run before pagination with a direction-matching ID tie breaker; newest first is the default. `order`, legacy `sort`, and `DATE_ASC`/`DATE_DESC` remain supported. Search debounces at 250 ms and preserves sort/page size.
- Editor catalogs stay off list pages. `/api/publish/product-type-choices` returns visible IDs/titles without presenter parameters. Selected `report_ids` must all exist and pass ACL/TLP checks (static 404 otherwise). The frontend intersects choices across sorted, deduplicated batches of 50 to bound URLs. Choices use the `product_type` cache keyed by selection; copy metadata uses `product_metadata`. Report, Story, and access changes invalidate both; config writes retain full invalidation. Report Publish choices are documented in [Analyze Reports](analyze-reports.md).
- A Product with restricted linked Reports remains readable under its Product Type ACL, but permits only title/description edits. `report_access_warning` explains the restriction. Preserve all links, publishing settings, and existing output; skip rendering on these saves. Copy/render/publish queue entry points reject restricted user requests; trusted jobs retain their behavior. Locked editors omit report selection from the strict choices lookup. Compatible-report metadata never exposes hidden Reports; see [RBAC](rbac-acl.md).
- HTML/JSON/text previews load on **Load preview** with an empty iframe sandbox. Keep the render in one inert template: HTMX can activate fallback iframes inside `noscript`, so the native fallback links to the authenticated download. PDF previews remain automatic.
- Render and manual Publish prompt to save dirty edits. Save and Continue resumes only after a successful save: Render queues rendering; Publish reopens the publisher chooser and still requires confirmation. The frontend strips the continuation field before model validation and accepts only these two actions; failures and restricted editors never resume. Product saves replace the complete editor to avoid duplicate IDs and stale Alpine state.
